# 打包与发布

> 本地开发运行（`npm run tauri:dev`）见 [开发环境.md](开发环境.md)。
> 本文讲怎么把 Skiller 打成用户可下载安装的客户端，以及怎么发布到 GitHub Releases。

## 两种运行方式的区别

| | dev 模式 | 打包产物 |
| --- | --- | --- |
| 命令 | `npm run tauri:dev` | `npm run tauri:build` |
| 前端 | vite dev server，热更新 | `npm run build` 静态产物嵌进二进制 |
| Rust | debug 编译，体积大、慢 | release 编译，优化后的独立 App |
| 用途 | 本机开发 | 发给用户安装 |

用户机器上不需要 Node、Rust 或源码，装的是编译好的原生 App。

## 本机打包（以 macOS 为例）

```bash
cd app
npm install
export PATH="$HOME/.cargo/bin:$PATH"
export CARGO_TARGET_DIR="/tmp/skiller-target"   # 绕开本机 EPERM，见开发环境.md
npm run tauri:build
```

`tauri build` 会先执行 `beforeBuildCommand`（`npm run build`，即
`tsc -b && vite build`），再编译 release 版 Rust 并生成安装包。首次 release
编译需要把全部依赖重新编一遍（debug 缓存不共用），耗时较长。

产物在 `$CARGO_TARGET_DIR/release/bundle/` 下：

- macOS：`macos/skiller.app`、`dmg/skiller_<版本>_<架构>.dmg`（本机实测约 18 MB）
- Windows：`nsis/`（`.exe` 安装程序）与 `msi/`（`.msi`）
- Linux：`deb/`、`appimage/`（视构建机可用工具而定）

两个本机注意点：

- `tauri.conf.json` 里 `bundle.macOS.signingIdentity` 固定为 `"-"`（ad-hoc），
  本地打出的 `.app` 自带有效签名，`codesign --verify` 可过；CI 里的
  `APPLE_SIGNING_IDENTITY` 环境变量同值，行为一致。将来接入正式 Developer ID
  时改这里或在 CI 注入真实 identity 即可（环境变量优先于配置）。
- DMG 阶段要调 `hdiutil` 挂载磁盘镜像，在受限沙盒终端里会报
  `bundle_dmg.sh` 失败；在普通终端（或放开沙盒）执行同一条命令即可正常出包。
  Rust 编译本身不受影响，失败重试时编译缓存可直接复用。

### 跨平台限制

Tauri 不支持交叉编译：在 macOS 上只能出 macOS 包，Windows / Linux 包要在
对应系统上构建。三平台全量发布走下面的 GitHub Actions，不需要自己准备
三台机器。

## 正式发布流程（GitHub Actions，四平台）

仓库已配好两个工作流（仓库根 `.github/workflows/`，构建步骤通过
`working-directory: app` / tauri-action 的 `projectPath: app` 进入应用目录），
发布分两步：

1. **Prepare Release**（手动触发）
   GitHub 仓库 Actions 页 → `Prepare Release` → Run workflow，选
   `patch` / `minor` / `major`。工作流执行 `npm run release:prepare`：
   同步 bump `package.json`、`src-tauri/tauri.conf.json`、三份 i18n 里的
   版本号，往两份 CHANGELOG 插入版本条目，然后提交并打 `v<版本>` tag
   推到 main。
2. **Build & Release**（tag 触发，自动）
   推送 `v*` tag 后自动运行，矩阵覆盖 macOS arm64 / macOS x64 /
   Windows x64 / Linux x64，各平台构建完成后把安装包传到同一个
   GitHub Release，并附上从 CHANGELOG 提取的中英双语发布说明。

发布完成后，用户在仓库的 **Releases 页**直接下载对应平台安装包。
App 内「设置 → 检查更新」走的是 GitHub releases/latest API
（`check_app_update` 命令），发现新版本会跳转到 Release 页下载，
不是静默增量更新。

### macOS 首次打开提示

CI 用 ad-hoc 签名（`APPLE_SIGNING_IDENTITY: -`），没有 Apple Developer
账号，Gatekeeper 会提示无法验证开发者。用户右键 App →「打开」即可放行，
这是无证书分发的标准做法。若以后申请了 Developer ID，可在 workflow 里
换成正式签名并加公证（notarization），提示即消失。Windows 侧同理，
未购代码签名证书时 SmartScreen 会有一次性拦截提示。

## 常用命令速查

```bash
# 只出当前平台的安装包（本机自测）
npm run tauri:build

# 只编译 release 二进制、不打安装包
cargo build --release --manifest-path src-tauri/Cargo.toml

# 发布前干跑版本号变更，不写文件
npm run release:prepare -- patch --dry-run
```
